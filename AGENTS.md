# Git workflow

- For every change, work on a feature branch and create a pull request targeting `main`.
- Never push directly to remote `main`.
- Agents may merge their pull requests after the required checks pass; no additional user confirmation is needed.

# Worktree lifecycle

The user requires at most one worktree per worker.

- Reuse the worker's assigned worktree for subsequent feature branches. Do not accumulate separate feature, QA, baseline, dashboard, or reconciliation checkouts for the same worker.
- Before starting work or creating a checkout, inspect the existing Git worktrees and chat attachments and reuse the assigned path. Independent DerivedData and result directories belong inside that worktree; parallel test jobs do not require additional source checkouts.
- The coordinator maintains the worker-to-worktree ownership map. The coordinator and release QA may use the shared main checkout for their existing roles without creating additional release or reconciliation worktrees.
- Preserve uncommitted source, unpushed commits, and needed ignored files before changing branches or retiring a checkout. Use managed archival for app-managed worktrees, retaining recoverable source and verified evidence copies with old-to-new path mappings.
- Retire obsolete auxiliary and baseline checkouts after all consuming jobs have actually exited and the coordinator acknowledges cleanup. Preserve current frozen source and Products while those jobs run, then complete consolidation.
- An additional worktree requires the user's explicit authorization for that specific exception. Completed features alone are not a reason to retain another checkout.

- Each worker writes an atomic, feature-specific `build/<feature>-ready-handoff.json` in the main checkout after verification/merge: feature, version/build, merge commit, tested/final heads, verification-summary path, unresolved failures, screenshot review and limits. Workers must not overwrite other workers' queue/ownership or phone state to compensate for delivery failures.
- The coordinator records last reconciliation, handoff acknowledgements, and `included_merges` for each combined artifact. Reconcile by source commit and artifact identity so repeated wakeups cannot duplicate builds/offers/installations. `Hold`/`Skip` and pending approval must not be converted into permission. If multiple already-merged features accumulated during an outage, delegate the latest verified combined main build to QA immediately and explicitly list all included features; do not downgrade through superseded previews.

- Prioritize QA's ready-feature main builds and approved installations, the coordinator's install approval questions, and simulator handoffs over dashboard polish or ancillary development.
- Workers implement and test on feature branches. They finish all applicable automated, affected-mode UI, screenshot, and integration checks, fix and retest failures, then merge their PR when everything passes. Their handoff includes the tested head, merge commit, results, screenshots, and any verification limits. Pending or failing worker checks mean the feature is not ready.
- QA uses the worker's completed verification evidence; do not repeat simulator testing or screenshot review after merge. QA builds clean merged `main` and verifies the build, signature/team, version/build, source identity, and binary/bundle hashes. Adopt an already completed build of the exact clean main source when its actual exit and source proof are available; do not rebuild identical source. Preserve any tested-versus-final source differences, affected-scope equivalence, historical failures, and verification limits. Preserve features already installed and never downgrade. # Leaf reader verification

The user explicitly requires all reading modes to be tested for future reader changes.

For changes to reading layout, navigation, appearance, or the floating chat UI:

- Exercise both Pages and Scroll with actual rendered books. Passing tests in one mode does not validate the other.
- Check forward and backward chapter boundaries, the beginning/end of the book, and restoration of the saved passage after closing and reopening.
- Check portrait and landscape, the affected fonts and margin settings, and Day/Paper/Night appearance. Typography or text-exclusion changes must cover the full 12–32 pt size range in both flows.
- Keep Ask Leaf open during book taps, text selection, and navigation. Dismiss it only with Close or an intentional downward swipe on the chat header. Dragging the top edge/grabber resizes the panel and must never dismiss it. Verify minimum/maximum height, saved size after reopening/rotation, and separate reading/keyboard size restoration without changing the book viewport or losing drafts/quotes.
- Check chat closed, open, and composing with the keyboard. The floating button is a translucent, draggable overlay. All lines must retain their normal reading width; do not reserve a gutter or reflow text around it. Exercise long-press, repeated dragging, tap-away dismissal, position restoration, and rotation in both flows.
- Inspect screenshots as well as text geometry. Verify that text remains visible through the button and there is no unnecessary reserved space.
- Include meaningful regression coverage for any discovered mode-specific failure. Report exactly which modes were tested and any remaining limitations.

Keep chapter loading lazy and preserve EPUB CFI meaning, bookmarks, and conversation history when changing text layout.
